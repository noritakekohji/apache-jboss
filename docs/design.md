# Apache / JBoss ログ分析ツール 設計メモ

更新日: 2026-11-27
状態: GC分析拡張

## 目的と前提

Windows端末上でApacheアクセスログ、JBossサーバーログ、Java GCログを読み込み、遅延、HTTPエラー、JBoss例外、Full GCの状況を調べる。利用者は一人、出力は他者と共有する。ログ時刻は日本時間、対象はおおむね1日分、利用規模は約20人。実ログの持ち出しは禁止し、開発時は合成データのみ使う。

## 実装方針

- Windows PowerShell 5.1とWindows Formsを使い、追加ランタイムや外部モジュールを要求しない。
- Apache Combined形式を基本とし、末尾の秒単位レスポンスタイムは任意項目として読む。標準Combinedだけでは処理時間が記録されないことを明示する。
- JBossの日時・ログレベル付きプレーンテキスト形式と、JDK 8系の旧形式およびJDK 9以降の統合GCログの代表的イベントを読む。Full GC、停止時間、ヒープ前後量、最大ヒープ、Full GC間隔を集計し、既知の詳細フェーズ行はイベント数へ重複計上しない。アプリケーション停止時間行も独立イベントとして扱う。未認識行は数と理由を報告する。
- ログIDを確認できない間はApache/JBossのイベントを取引単位で結びつけない。時間的な近さを因果と誤認させない。
- HTMLはクエリ文字列を除き、外部CDNを使わない。CSVもURLクエリを既定で削り、数式インジェクションを防ぐ。

## GCViewerを参考にした機能

GCViewerの変更履歴にあるGC方式・JVMログ形式の追随、イベント詳細、停止時間の分布、ヒープ推移とイベント詳細、Full GC間隔の指標を参考にした。GCViewerはJDK 25のParallel GCフェーズ、統合ログ装飾、ZGC/Shenandoah対応を更新している。本ツールでは現時点で主要な旧形式と統合形式の一部だけを独自実装し、GCViewerのコードは取り込んでいない。変更履歴を確認した日: 2026-11-27。参照: [GCViewer Changelog](https://github.com/chewiebug/GCViewer/wiki/Changelog)。

## 初期版の制限

初期GUIと集計は基本機能の実装段階である。Apache Combinedの標準形式には処理時間欄がないことが多く、その場合レスポンスタイム指標は空になる。JBossログの複数行スタックトレースは現在は個別行扱い。GC形式はJavaバージョン・ベンダーで異なるため、実環境との適合をログを持ち出さず利用端末上で確認する必要がある。Java 25を含む全GCアルゴリズム/装飾子の網羅的解析、インタラクティブな時系列比較、期間フィルター、エンコード選択、マスキングプレビューは今後の改善項目。

## 起動方法

`Start-ApacheJbossLogAnalyzer.bat`を用意する。PowerShell起動引数で`-ExecutionPolicy Bypass`を指定し、この子プロセスに限って実行ポリシー確認を省略する。ユーザー/コンピューターの恒久的なポリシーは変更せず、管理者権限にも昇格しない。Group Policy、AppLocker、WDACなどの端末管理制御は引き続き適用される。

## 共有出力

HTMLレポートとリクエスト/JBoss/GC別CSVをデスクトップに出力する。GC CSVには停止時間、原因、前後ヒープ量、最大ヒープ量を含める。ログ本文はHTMLに含めず、URLクエリ文字列は除外する。出力先を選ぶ機能やプレビューは次段階で追加する。
